# การจัดอันดับผลค้นหา

การค้นหาใช้คะแนนร่วมกัน โดยไม่เปลี่ยนตัวกรอง สิทธิ์การเข้าถึง หรือหน้าตาเดิม

- รหัสตรงทั้งคำ: 6 คะแนน
- รหัสขึ้นต้นตรงคำค้น: 5 คะแนน
- คำค้นอยู่ด้านในรหัส: `3 + 1 / (ตำแหน่ง + 1)` คะแนน ตำแหน่งเริ่มจาก 0
- ชื่อหรือรายละเอียด: ตรงทั้งคำ 3 คะแนน, ขึ้นต้น 2 คะแนน, ด้านใน `1 / (ตำแหน่ง + 1)` คะแนน
- ใช้คะแนนสูงสุดจากแต่ละช่อง ไม่รวมคะแนนซ้ำจากชื่อหรือรหัสสำรอง
- ไม่แยกตัวพิมพ์ใหญ่–เล็ก ตัดช่องว่างหัวท้าย และนับตำแหน่งแบบ Unicode code point
- คะแนนเท่ากันใช้ลำดับเดิม คำค้นว่างไม่เปลี่ยนลำดับ

`src/lib/searchRanking.ts` ใช้กับรายการหน้าเว็บและตัวเลือกใน dialog โดย `rankSearchResults` จัดลำดับเท่านั้น ไม่กรองรายการออกเอง หน้าไม่มีรหัสสินค้าใช้รหัสเอกสารหรือชื่อหลักที่ค้นหาแทน

`server/lib/searchRanking.js` ใช้คะแนนเดียวกันกับ API ที่แบ่งหน้า โดยจัดอันดับก่อน `skip`/`limit` และใช้ลำดับเดิมตามด้วย `_id` ตัดสินคะแนนเท่ากัน ไม่ส่งคะแนนภายในกลับไปกับข้อมูล ผู้ใช้พิมพ์เครื่องหมายพิเศษได้โดยไม่ถูกตีความเป็นคำสั่ง MongoDB หรือ regex

ตัวเลือกที่รองรับ fuzzy search หรือสลับแป้นไทย–อังกฤษยังคงรูปแบบการจับคู่เดิม ผลตรงข้อความจริงมาก่อน fuzzy-only และจัดอันดับข้ามกลุ่มก่อนแสดงหัวกลุ่ม

## การตรวจสอบโดยไม่ build

```powershell
npx.cmd vitest run src/lib/searchRanking.test.ts
npm.cmd --prefix server test -- --runInBand lib/searchRanking.test.js
node --test server/routes/searchRanking.test.js
$env:RUN_MONGO_SEARCH_TESTS = "1"
npm.cmd --prefix server test -- --runInBand lib/searchRanking.mongo.test.js
```

การทดสอบ Mongo ใช้ URI จาก `server/.env` หรือ local default ส่งเฉพาะข้อมูลจำลองผ่าน `$documents` แบบอ่านอย่างเดียว ไม่อ่านหรือเขียนเอกสารจริง เปรียบเทียบลำดับกับ JavaScript และตรวจการแบ่งหน้า
